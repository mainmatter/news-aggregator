# Source Participation Logging Plan

## Goal

Add durable, per-edition visibility into why a source did or did not contribute articles, without cluttering edition pages.

## Final Product Decisions

- Keep edition pages focused on editorial content.
- Surface source participation in `/sources` via an expandable **Generation History** area per source.
- Persist per-edition source outcomes so users can audit past runs.
- Use free-text source-level reasons (agent-authored when available).
- Show recent runs inline on `/sources` (last **12**) and provide a dedicated full-history page per source.
- On `/sources`, keep technical errors hidden.
- On the dedicated full-history page, technical errors are available via per-row disclosure.

## Implementation Plan

### 1) Persist generation history (DB)

Create two new tables:

- `edition_generation_run` (one row per generation invocation)
  - `id`, `user_id`, `daily_edition_id`, `edition_date`, `status`
  - aggregate counts: `total_sources`, `active_sources`, `successful_sources`, `failed_sources`, `skipped_sources`, `published_articles`
  - `error_message`, `started_at`, `finished_at`, timestamps
- `source_participation_log` (one row per source per run)
  - `id`, `generation_run_id`, `user_id`, `daily_edition_id`, `edition_date`
  - source linkage/snapshots: `user_source_id` (nullable), `source_id` (nullable), `source_display_name_snapshot`, `source_canonical_url_snapshot`
  - outcome fields: `status`, `selected_article_count`, `reason`, `error_message`, `started_at`, `finished_at`, timestamps

Resolved schema constraints/rules:

- Statuses are enforced at TypeScript/Valibot level (no DB CHECK constraints in v1).
- `selected_article_count` is `NOT NULL DEFAULT 0`.
- All run counters are `NOT NULL DEFAULT 0`.
- `started_at` defaults to now; `finished_at` stays nullable until terminal state.
- Unique index on `(generation_run_id, user_source_id)` for one participation row per source per run.
- FK behavior:
  - `source_participation_log.generation_run_id` -> `edition_generation_run.id`: `ON DELETE CASCADE`
  - `source_participation_log.user_source_id` / `source_participation_log.source_id`: `ON DELETE SET NULL`
  - run rows cascade with edition deletion (edition delete removes that run history).
- Add indexes for read/write paths:
  - `source_participation_log(user_source_id, finished_at)`
  - `source_participation_log(generation_run_id)`
  - `edition_generation_run(user_id, edition_date)`

Critical files:

- `src/lib/server/db/schema.ts`
- `drizzle/*` (generated migration files)

### 2) Prepare-time run creation and frozen snapshot

- In generation preparation/start, create an `edition_generation_run` row and attach `generation_run_id` to workflow input.
- Also capture a frozen source snapshot in preparation state (active + inactive), and use that same snapshot for:
  - participation seeding,
  - active execution set,
  - in-memory aggregate computation.
- Keep `generation_run_id` in workflow input types.
- If `workflow/api.start` fails after preparation/seeding, mark run failed and finalize queued participation rows to error.

Special start behavior:

- If user has **zero sources total**: fail validation and create no run row.
- If all sources are inactive: short-circuit before workflow start:
  - create run + skipped participation logs,
  - finalize run as completed,
  - apply edition finalization semantics equivalent to `persist_edition([])`,
  - do not call `workflow/api.start`.

Critical files:

- `src/lib/server/edition_generation.ts`
- `src/workflows/generate_daily_edition/types.ts`

### 3) Record source participation via workflow steps

Important constraint: DB mutations tied to workflow orchestration must happen in **step functions**.

- Reuse existing step files where possible:
  - finalize run success path in `persist_edition.ts`
  - finalize run failure path in `mark_generation_failed.ts`
- Add minimal new step(s) only where existing steps do not fit (e.g., participation seed / mark running / finalize source result).
- Do not perform DB mutations directly in workflow orchestration function bodies.

Execution behavior:

- Seed participation rows from frozen snapshot:
  - inactive => `skipped` with exact reason: `Source inactive when generation started.`
  - active => `queued`
- For each active source run:
  - mark `running` before sandbox launch
  - finalize as:
    - `success` + selected count
    - `error` + free-text reason/error
- Success with 0 links counts as `success` with `selected_article_count = 0`.
- On workflow-level failure, convert any remaining `queued`/`running` rows to `error` with:
  - `Generation aborted before source completed: <error_message>`
- Keep in-memory aggregate computation policy (using frozen snapshot + source results).

Critical files:

- `src/workflows/generate_daily_edition/index.ts`
- `src/workflows/generate_daily_edition/steps/persist_edition.ts`
- `src/workflows/generate_daily_edition/steps/mark_generation_failed.ts`
- `src/workflows/generate_daily_edition/steps/*` (minimal new step(s) for participation transitions)
- `src/lib/server/source_participation.ts` (new helper module)

### 3.1) Reason handling policy

- Source-level `reason` remains free text and should be persisted verbatim when provided.
- Add optional **top-level** `reason` to source callback payload.
- Keep existing article-level `reason` field untouched, but it is out-of-scope for this plan.
- If success has 0 links and callback lacks reason, use fixed fallback:
  - `No articles were selected for this source, and no reason was provided.`
- If run fails before agent reason exists (timeout/system failure), mirror raw system error into both `reason` and `error_message`.
- Keep reason concise in runner prompt guidance (target ~140–220 chars), but store full text as received.

Runner/callback specifics:

- `choose_links` returns `{ urls, reason }`.
- For normal success with links, source-level `reason` may be null.
- For runner error callbacks, send both `error` and `reason` (same raw message).
- Do not add `generation_run_id` to callback payload in v1.

Critical files:

- `src/workflows/generate_daily_edition/types.ts`
- `src/workflows/generate_daily_edition/sandbox/runner.js`
- `src/workflows/generate_daily_edition/steps/consume_source_webhook.ts`

### 4) Expose source run history in queries

- Extend source query model for `/sources` to return all current sources with recent participation history.
- Per-source recent rows: last **12**, newest-first, include in-progress states (`queued`, `running`).
- Add dedicated full-history query for one source with page-number pagination.
- Full-history query must return:
  - page rows,
  - `total_count`,
  - normalized/clamped page metadata.
- Pagination rules:
  - default page size: **50**
  - invalid/missing/non-positive page => clamp to 1
  - page above max => clamp to last page
  - no redirect required; clamp in data layer.

Critical files:

- `src/lib/sources.remote.ts`

### 5) UI: recent history on `/sources`

- Add `<details>` expandable **Generation History** section per source.
- Keep `<details>` collapsed by default on load.
- Use plain summary label (`Generation History`) without an extra latest-run summary line.
- Show friendly status labels in UI:
  - success => Succeeded
  - error => Failed
  - skipped => Skipped
  - running => Running
  - queued => Queued
- Show numeric selected counts (including `0` for non-success states, per chosen policy).
- Show readable reason text when present.
- Hide technical error details on `/sources`.
- Always show `View all runs` link (even when source has no runs yet).

Critical files:

- `src/routes/sources/+page.svelte`
- `src/routes/layout.css` (only if additional shared tokens are needed)

### 6) UI: dedicated source-history page (full run list)

- Add route: `/sources/[user_source_id]/runs`.
- Render paginated history list/table with:
  - edition date
  - run status
  - selected article count
  - reason
  - finished timestamp (fallback to started timestamp for in-progress rows)
- Include source display name in page header plus back link to `/sources`.
- Show technical errors via per-row disclosure (not always-visible column).
- Show source URL snapshot per row.
- Show snapshot display name only when it differs from current display name.
- Pagination UI: `Previous` / `Next` + `Page X of Y`.
- Unauthorized/non-owned source id should resolve as not found.

Critical files:

- `src/routes/sources/[user_source_id]/runs/+page.svelte`
- `src/lib/sources.remote.ts`

## Scope Notes

- This plan intentionally avoids adding participation details to edition pages in v1.
- No historical backfill in v1; history starts after rollout.
- No live polling/websocket updates in v1; updates appear on refresh/navigation.
