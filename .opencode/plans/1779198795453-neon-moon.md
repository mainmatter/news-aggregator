# Mainmatter-Inspired Visual Redesign Plan

## Context

- Product register: product UI, from `PRODUCT.md`.
- Users: personal readers and knowledge workers using a focused daily digest.
- Product tone: editorial, calm, exacting, with reading first and controls secondary.
- `DESIGN.md` is missing, so implementation should use `PRODUCT.md`, the product register reference, and `.redesign` as the design source.
- Mainmatter source cues from `.redesign`: flat purple/aqua/black sections, sharp edges, large sans typography, generous spacing, arrow CTAs, bottom-border forms, strong simple dividers, sparse layouts.

## Design Direction

- Scene: a reader checks a daily digest on a laptop in a bright workspace, then tunes sources without leaving a focused reading mode. This supports a light/off-white default, with dark mode preserved as a functional preference rather than the primary aesthetic.
- Color strategy: restrained product UI with committed moments. Use off-white and tinted black for the reading surface, purple for primary action/current state, aqua for focus/hover/support accents, and black for decisive section bands.
- Typography: replace the serif newspaper voice with a Mainmatter-like sans system using installed fontsource packages. Prefer `Source Sans 3` or `DM Sans` as the closest available legal substitute for Core Sans A. Avoid display fonts in UI labels.
- Shape and surface: sharp edges, minimal shadows, strong borders/rules, no nested card grids, no side-stripe accents, no gradient text, no decorative glass.
- Motion: keep short state transitions and hover arrow movement only. Respect reduced motion.

## Implementation Steps

1. Update global design tokens in `src/routes/layout.css`.
   - Convert color tokens to OKLCH equivalents for Mainmatter-inspired off-white, tinted black, purple, aqua, gray, semantic success/error.
   - Add reusable section/action tokens only if they are used across multiple components.
   - Replace current warm newspaper texture/serif assumptions with sharp product defaults.
   - Keep existing token names where possible to reduce churn.

2. Update global shell in `src/routes/+layout.svelte`.
   - Replace `Fraunces`/`Outfit` imports with the chosen installed sans font imports.
   - Restyle the fixed top rule as a thin Mainmatter brand strip or compact accent line.
   - Preserve `ModeToggle`, favicon, view transitions, and child rendering.

3. Redesign shared primitives first.
   - `src/lib/components/Button.svelte`: flat rectangular buttons, sharp radius, clear primary/secondary/ghost states, preserved feedback behavior.
   - `src/lib/components/Masthead.svelte`: large sans masthead, spacious, no italic newspaper styling.
   - `src/lib/components/PageHeader.svelte`: stronger structured header/nav rhythm.
   - `src/lib/components/NavLink.svelte`: compact link treatment with underline/arrow-like motion as appropriate.
   - `src/lib/components/SectionRule.svelte`: stronger flat divider language.
   - `src/lib/components/PageFooter.svelte`: align copy and spacing with the new system.
   - `src/lib/components/ArticleMeta.svelte`: slash-separated or compact metadata, readable on color sections.

4. Redesign article presentation.
   - `src/lib/components/FeaturedArticle.svelte`: remove drop cap and serif cues; create a roomy lead section with strong sans headline, flat color/accent treatment, and a clear read CTA.
   - `src/lib/components/Article.svelte`: preserve trim logic and links; make list/grid items sharp, scannable, and Mainmatter-like without becoming identical generic cards.
   - `src/lib/components/EditionsList.svelte`: restyle date pills/strip to match flat action vocabulary and selected-state tokens.

5. Redesign main reader route in `src/lib/EditorialDesign.svelte`.
   - Preserve all remote calls, derived state, optimistic generation overrides, sign-out form, and article rendering logic.
   - Restyle `.page-container`, `.content`, `.grid`, `.edition-state-panel`, `.generation-button`, and `.sign-out-btn`.
   - Make missing/generating/failed/empty states deliberate flat panels with clear hierarchy and actions.

6. Redesign auth route in `src/routes/+page.svelte`.
   - Preserve `login_or_register`, `sign_in_google`, form fields, submit values, and `FieldErrors`.
   - Create a spacious split auth/landing composition with Mainmatter-inspired type, bottom-border inputs, and flat CTAs.
   - Keep copy concise and avoid adding decorative marketing bloat.

7. Redesign management and archive routes.
   - `src/routes/sources/+page.svelte`
   - `src/routes/editions/+page.svelte`
   - `src/routes/editions/[date=date]/+page.svelte`
   - `src/routes/news/archives/+page.svelte`
   - Preserve every form binding, `enhance` handler, hidden field, delete action, checkbox/select behavior, optimistic update, and link.
   - Use structured editorial tool layouts: section bands, strong dividers, bottom-border controls, compact status badges with text labels, and consistent button vocabulary.

8. Responsive and accessibility pass.
   - Check mobile, tablet, and desktop for masthead wrapping, nav stacking, article readability, form controls, source/edition action rows, and editor density.
   - Maintain semantic headings, labels, WCAG AA contrast, visible focus states, keyboard-accessible controls, and reduced-motion-safe interactions.

## Constraints

- Visual changes only. Do not change data loading, auth, remote functions, server code, schemas, routes, or behavior.
- Use `apply_patch` for manual edits.
- Use the Svelte tooling/autofixer when editing `.svelte` files during implementation.
- Reuse or extend `src/routes/layout.css` tokens instead of scattering raw values.
- Do not add Google Font links. Use installed `fontsource` packages only.
