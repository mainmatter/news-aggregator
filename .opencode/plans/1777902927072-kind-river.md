# Sentry setup plan (Full + AI telemetry)

## Current state from your Sentry wizard diff

- Baseline Sentry wiring is now present in `package.json`, `src/hooks.server.ts`, `svelte.config.js`, `vite.config.ts`, `src/hooks.client.ts`, `src/instrumentation.server.ts`, and `.gitignore`.
- The generated config currently hardcodes DSN and org/project values in source files, enables `sendDefaultPii: true`, and has no workflow/sandbox AI instrumentation yet.
- The updated plan below focuses only on the remaining work needed to match your request (full setup + Seer-friendly AI telemetry + privacy-safe defaults).

## Recommended implementation (remaining work)

1. **Harden generated Sentry config (remove hardcoded values)**
   - Replace hardcoded DSN in `src/hooks.client.ts` and `src/instrumentation.server.ts` with env-driven config.
   - Replace hardcoded `org`/`project` in `vite.config.ts` with env-driven values.
   - Keep `.env.sentry-build-plugin` ignored (already added in `.gitignore`).

2. **Apply privacy-safe defaults for client capture and replay**
   - In `src/hooks.client.ts`, set `sendDefaultPii` to disabled by default.
   - Configure replay with privacy-first options (`maskAllText`, `blockAllMedia`) while keeping error-session sampling enabled.
   - Add event/breadcrumb scrubbing logic for auth headers, cookies, webhook secrets, and provider API keys.

3. **Refine server hook integration without changing behavior**
   - Keep Sentry first in the chain in `src/hooks.server.ts`.
   - Preserve existing theme/auth behavior and `handleError` export.
   - Optionally simplify nested `sequence(...)` shape during implementation if no behavior change is introduced.

4. **Add workflow-level tracing + structured error capture**
   - Instrument `src/lib/server/edition_generation.ts` and `src/workflows/generate_daily_edition/index.ts` with generation root span + per-source child spans.
   - Capture failures with tags/context (`edition_id`, `edition_date`, `source_id`, `stage`) and normalized fingerprints for timeout/signature/sandbox-launch/callback failures.

5. **Propagate trace context into sandbox execution**
   - Extend `src/workflows/generate_daily_edition/sandbox/shared.ts` to pass trace continuation values into sandbox env.
   - Pass correlation ids from host workflow to sandbox and back through callback payload/processing.

6. **Instrument sandbox runner for AI telemetry (metadata-only)**
   - Update `src/workflows/generate_daily_edition/steps/launch_source_sandbox.ts` to install `@sentry/node` in sandbox before `runner.js` execution.
   - Initialize Sentry in `src/workflows/generate_daily_edition/sandbox/runner.js` with continued trace context.
   - Add manual spans around `choose_links`, each `summarize_article`, and callback posting.
   - Send only metadata (model/provider/latency/article counts/status/error type), never raw prompts/responses.

7. **Upgrade error hotspots from plain console logs to Sentry events**
   - Add structured capture (while keeping useful local logs) in:
     - `src/workflows/generate_daily_edition/steps/launch_source_sandbox.ts`
     - `src/workflows/generate_daily_edition/steps/stop_sandbox.ts`
     - `src/workflows/generate_daily_edition/steps/consume_source_webhook.ts`
     - `src/routes/.well-known/workflow/v1/webhook/[token]/+server.js`

8. **Add env docs placeholders (values still provided by you)**
   - Update `.env.example` with Sentry keys used by runtime/build plugin and optional release fields.

9. **TDD coverage for observability helpers and failure paths**
   - Add failing tests first for redaction/trace-context helpers and workflow failure instrumentation.
   - Implement until server Vitest suite is green.

## Verification plan

1. **Static checks**
   - Run `pnpm check`.

2. **Unit tests (TDD + regression)**
   - Run `pnpm test:unit -- --run`.
   - Confirm new observability tests and existing suites pass.

3. **Build/source-map validation**
   - Run `pnpm build`.
   - Confirm Sentry Vite plugin executes cleanly and release/source map upload path is correct.

4. **Manual Sentry validation**
   - Trigger a browser error and verify mapped stack traces and replay privacy settings.
   - Trigger a server error and verify grouping/tags.
   - Run a daily edition generation and verify:
     - workflow root + child spans,
     - sandbox AI spans/events,
     - host/sandbox trace correlation,
     - metadata-only AI payloads (no raw prompt/response).

5. **Privacy validation**
   - Inspect emitted events to ensure secrets/tokens/cookies are scrubbed.
   - Confirm PII defaults remain disabled unless intentionally enabled later.
